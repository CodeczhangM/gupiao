# 实时信息筹码峰与底部洗盘建仓信号设计

## 目标与范围

在“实时信息”页面的三个盘中阶段模块中加入筹码峰信息、底部洗盘评分和建仓提示：

- 缩量企稳观察
- 底部首阳触发
- 底部放量启动

筹码信号参与每个模块内部排序，但不作为硬过滤条件。筹码数据缺失时保留原候选和原有排序能力。

“盘末隔夜溢价 TOP20”保持不变：不获取、不注入、不显示筹码字段，也不改变其评分、排序、缓存和接口结构。

## 数据来源

### 直接筹码数据

复用项目已经配置的 Tushare 连接：

- `cyq_chips`：指定股票和交易日的逐价格档筹码占比，用于识别主峰与次峰。
- `cyq_perf`：5%、15%、50%、85%、95%成本分位、加权平均成本和获利比例。

服务端只为三个盘中模块涉及的去重股票代码获取筹码数据。相同股票、交易日的结果进入进程内缓存，缓存键包含股票代码和交易日；30秒实时刷新复用当日缓存。强制刷新只补取当日缺失或失败的数据，不重复刷新已有的当日有效筹码。

### 行情上下文

复用实时信息现有历史日线，使用最近最多120个有效交易日的最高价和最低价判断筹码峰所处位置。不得使用 `cyq_perf.his_low` 计算底部位置，因为该字段在部分股票上可能为零或受到长期复权历史影响。

## 指标定义

所有百分比输出均使用百分数单位，例如 `12.5` 表示12.5%。除展示值外，计算中保留完整精度。

### 筹码峰

- 主筹码峰价：`cyq_chips.percent` 最大价格档的 `price`。
- 主筹码峰占比：该档的 `percent`。
- 次筹码峰：排除与主峰价距离小于主峰价2%的相邻价格档后，剩余档位中占比最高者。
- 无满足间距的价格档时，次峰相关字段为空。

### 成本密集度

- 70%密集度：`(cost_85pct - cost_15pct) / (cost_85pct + cost_15pct) * 100`。
- 90%密集度：`(cost_95pct - cost_5pct) / (cost_95pct + cost_5pct) * 100`。
- 分母小于等于零、成本缺失或高成本小于低成本时，该密集度为空。

### 底部位置与峰价距离

- 主峰底部位置：`(主峰价 - 120日最低价) / (120日最高价 - 120日最低价) * 100`。
- 峰价距离：`(当前价 / 主峰价 - 1) * 100`。
- 日线不足20个有效交易日、最高价不大于最低价或价格无效时，底部位置为空，但其他可计算指标继续输出。

## 底部洗盘评分

评分满分100分，由五部分相加。任一部分数据缺失时该部分记零，同时通过 `chip_data_complete` 标记完整性；不把缺失解释为负面信号。

### 1. 筹码密集度：30分

分别计算70%和90%密集度得分，取较高者：

- 70%密集度不高于10%：30分；不高于15%：24分；不高于20%：12分；否则0分。
- 90%密集度不高于10%：30分；不高于15%：24分；不高于20%：12分；否则0分。

这使“70%或90%筹码密集度在10%～15%以内”都能形成有效确认。

### 2. 主峰底部位置：25分

- 不高于20%：25分。
- 不高于35%：18分。
- 不高于50%：8分。
- 高于50%：0分。

### 3. 当前价贴近主峰：20分

- 峰价距离在 -3% 至 +8%：20分。
- 在 -8% 至 +15%，但不属于上一档：12分。
- 在 -12% 至 +20%，但不属于前两档：5分。
- 其他：0分。

### 4. 洗盘结构：15分

复用现有实时底部结构字段：

- `bottom_consolidation` 为真：5分。
- `bottom_volume_contraction <= 0.8`：5分。
- `bottom_ma_convergence_pct <= 5`：5分。

字段缺失时对应项为零。筹码指标不会改变现有底部结构计算。

### 5. 获利盘结构：10分

- `winner_rate` 在20%至65%（含边界）：10分。
- 在10%至80%，但不属于上一档：5分。
- 其他：0分。

该项避免把几乎全部获利的高位一致状态误认为底部洗盘，同时允许低获利盘的筑底状态获得部分分数。

## 信号分级与建仓条件

- 80～100：`底部洗盘 · 可建仓`
- 65～79.999：`底部筹码密集 · 等待确认`
- 45～64.999：`筹码整理`
- 0～44.999：`筹码结构偏弱`
- 主峰或两个密集度均不可用：`筹码数据暂缺`

`chip_build_position` 仅在评分不低于80、主峰底部位置不高于35%、峰价距离处于 -8% 至 +15%，且70%或90%密集度不高于15%时为真。该布尔值是模块内部最高优先级的排序信号，也是前端“可建仓”强调样式的唯一依据。

该信号是量化辅助提示，不执行交易，也不改变候选所属的 observation、trigger 或 launch 阶段。

## 服务端结构与数据流

新增独立筹码分析服务，负责：

1. 规范股票代码和交易日。
2. 获取、缓存并校验 `cyq_chips` 与 `cyq_perf`。
3. 从历史日线构造120日价格区间。
4. 计算筹码指标、评分、标签和理由。
5. 将结果批量附加到盘中候选行。

实时信息流程在完成盘中候选构造、进入 `_group_realtime_stage_rows` 之前附加筹码字段。三个阶段共享同一份已去重查询结果。

每个盘中候选新增以下稳定字段：

- `chip_peak_price`
- `chip_peak_percent`
- `chip_secondary_peak_price`
- `chip_secondary_peak_percent`
- `chip_concentration_70_pct`
- `chip_concentration_90_pct`
- `chip_peak_bottom_position_pct`
- `chip_price_distance_pct`
- `chip_weighted_avg_cost`
- `chip_winner_rate`
- `chip_washout_score`
- `chip_washout_label`
- `chip_washout_reason`
- `chip_build_position`
- `chip_data_complete`
- `chip_data_trade_date`
- `chip_data_warning`

模块排序在原排序键之前增加：

1. `chip_build_position`，真值优先。
2. `chip_washout_score`，高分优先。
3. 各模块现有排序键，顺序保持不变。

总列表 `stocks` 维持现有排序，只有 `observation_stocks`、`trigger_stocks` 和 `launch_stocks` 使用筹码优先排序，从而把影响严格限定在用户指定的三个模块。

## 错误处理与降级

- 单只股票请求失败不得中断整个实时信息构建。
- 缺失或异常响应生成空筹码字段、`chip_washout_label="筹码数据暂缺"` 和简短的 `chip_data_warning`。
- 筹码警告汇总到盘中模块的 `fallback_warnings`，去重后保留有限数量，避免污染页面。
- 缓存中不得永久保存失败结果；失败结果使用短暂退避，下一次刷新可重试。
- Tushare 未配置或接口无权限时，三个模块完整保留原候选，隔夜模块不受影响。

## 前端展示

三个阶段共用的表格新增“筹码峰”列，位于“抗跌力”之后、“60分信号”之前。单元格展示：

- 第一行：建仓标签和洗盘评分。
- 第二行：主峰价格、主峰占比和当前价距主峰。
- 第三行：70%与90%密集度。

`chip_build_position=true` 使用强信号样式；等待确认使用观察样式；结构偏弱使用风险样式；数据暂缺使用弱化样式。详细原因放入单元格 `title`，避免继续加宽表格。

三个阶段表格的空状态 `colspan` 随新增列调整。隔夜溢价表格及其详情区域不增加筹码内容。

## 缓存版本

实时信息数据库缓存键和成功结果缓存键加入筹码规则版本。旧缓存可以作为备用结果读取，但前端按字段缺失显示“筹码数据暂缺”，不得把旧缓存中的候选删除。新结果写入新版本缓存键。

## 测试与验收

服务端单元测试覆盖：

- 70%和90%密集度在10%、15%边界的评分。
- 无效成本分位与零分母。
- 主峰、间隔2%的次峰识别。
- 120日底部位置和峰价距离。
- 五部分评分与四个有效信号等级。
- `chip_build_position` 的全部必要条件。
- 单股失败和完全无权限时的降级。
- 相同股票跨三个阶段只加载一次筹码。
- 三个阶段按可建仓与评分优先、随后维持原排序键。
- 总列表维持原排序。
- 隔夜构建函数调用参数、隔夜股票字段和隔夜前端模板均不发生筹码改动。

前端工具与布局测试覆盖：

- 四类标签与数据暂缺的文本、样式和详情。
- 数值缺失时显示 `--`，不显示 `NaN`。
- 三个阶段表格包含筹码峰列。
- 隔夜溢价表不包含筹码峰列或筹码详情。

验收时运行相关 Python 测试、前端 Node 测试和完整测试套件，并核对一次真实股票返回的主峰、密集度、评分及排序结果。
