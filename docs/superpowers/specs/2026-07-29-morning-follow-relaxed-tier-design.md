# 次日早盘跟进宽松分层设计

## 目标与范围

在现有外层“次日早盘跟进”板块中，保留通过个股 60 分钟模型、
但未完全满足尾盘三项条件的股票，并通过备注明确风险。宽松候选在
次日早盘确认全部通过后，可以升级为“谨慎跟进”。

本次仍只修改外层次日早盘跟进链路。以下内容保持不变：

- “实时信息”页面中的“隔夜选股”；
- `realtime_info_service.py`；
- `build_overnight_monitor`；
- `/overnight-monitor` 及其 Java 代理；
- 原有实时信息字段、标签和排序。

## 硬门槛

所有展示候选仍必须满足：

- 原有日线硬筛选，包括非 ST、非科创板、价格、涨幅、换手率、
  有效量比和成交额条件；
- 个股 60 分钟 MACD/KDJ 模型通过；
- 板块 60 分钟 MACD/KDJ 信号存在且不得向下；
- 个股 60 分钟、前日尾盘分钟数据完整。

个股 60 分钟模型不通过、板块向下、板块信号缺失或必要分钟数据
缺失时，股票不进入展示列表。

## 尾盘条件分层

原有尾盘三项条件从绝对淘汰条件改为分层评分条件：

- 14:30 后涨幅 `0.15%–1.20%`；
- 尾盘量能 `1.20–3.00` 倍；
- 尾盘收盘位置 `>= 0.75`。

每满足一项获得 10 分尾盘分，尾盘部分满分 30 分。输出以下字段：

- `tail_condition_pass_count`：满足项数，取值 0–3；
- `tail_conditions_all_pass`：三项是否全部满足；
- `tail_condition_notes`：未满足项的中文备注列表；
- `setup_tier`：`strict` 或 `relaxed`；
- `setup_tier_label`：`严格候选` 或 `宽松观察`。

备注必须写出实际值和目标区间，例如：

- `尾盘涨幅0.11%，低于0.15%`；
- `尾盘量能0.85倍，低于1.20倍`；
- `尾盘收盘位置57%，低于75%`；
- 超过上限时使用“高于”文案。

三项全部满足且总分不低于 70 分时为 `strict`。只要硬门槛通过，
即使尾盘条件未全部满足或总分低于 70，也保留为 `relaxed`。
龙头身份仍只加分，不能绕过任何硬门槛。

## 状态转换

前日观察阶段：

- `strict` 显示“明日观察”；
- `relaxed` 显示“宽松观察”。

次日 9:35 前，两类候选均显示“等待9:35确认”。9:35 后继续使用
现有开盘幅度、当前价、前五分钟 VWAP、涨幅和尾盘支撑规则：

- 触发放弃条件时，两类候选都显示“放弃”；
- 未完全确认且未触发放弃时显示“等待确认”；
- 早盘条件全部通过时，`strict` 显示“可以跟进”；
- 早盘条件全部通过时，`relaxed` 显示“谨慎跟进”。

“谨慎跟进”不是自动下单建议。其买入计划固定包含“仅轻仓考虑、
不可追高、尾盘条件未完全确认”，并继续遵守普通 A 股 T+1：
买入后最早下一交易日卖出。

## 排序与页面

状态排序为：

1. 可以跟进；
2. 谨慎跟进；
3. 等待确认；
4. 等待9:35确认；
5. 明日观察；
6. 宽松观察；
7. 数据未就绪；
8. 放弃。

同状态内按观察分、尾盘满足项数、尾盘收盘位置和成交额降序。

外层表格保留现有列，在最后一列中依次展示：

- 严格候选或宽松观察标签；
- 尾盘未满足条件备注；
- 早盘跟进原因；
- 买入条件；
- T+1 退出计划。

“谨慎跟进”使用黄色观察标签；“可以跟进”继续使用绿色标签；
“放弃”和“数据未就绪”继续使用风险标签。

## 接口与兼容

继续使用独立接口：

- Python `/api/morning-follow-monitor`；
- Java `/api/quant/morning-follow-monitor`。

接口只增加分层和备注字段，不修改旧接口，不删除现有字段。
前端继续沿用 `overnightMonitor` 状态对象，避免扩大修改范围。

## 测试与真实数据验证

新增或调整测试以证明：

- 尾盘三项未全部满足但硬门槛通过时，股票仍被返回；
- 每个未满足条件都有包含实际值的备注；
- 三项全部满足且总分达标时仍为严格候选；
- 宽松候选早盘全部确认后变为“谨慎跟进”；
- 宽松候选触发风控时仍为“放弃”；
- 个股 60 分模型失败、板块向下或数据缺失时仍被淘汰；
- 前端正确映射“宽松观察”和“谨慎跟进”标签。

使用 2026-07-29 当前缓存复核漏斗。预期排名前 30 只中，通过个股
60 分钟模型且板块未向下的 11 只能够以严格或宽松分层显示；实际
数量随交易数据变化，不写成固定单元测试断言。

回归测试必须继续证明实时信息中的“隔夜选股”区块和
`realtime_info_service.py` 没有发生变化。
