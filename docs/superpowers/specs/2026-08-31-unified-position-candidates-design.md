# 统一观察与建仓候选设计

## 目标

将实时信息页中的“缩量企稳观察”“底部首阳触发”“底部放量启动”三张表合并为一张“近期观察与建仓”候选表。系统继续保留三种底部阶段作为因子和说明，但不再分别排行。统一候选池按保守型多因子模型评分，只展示具备实际观察或建仓价值的前 5 至 10 只股票；符合条件不足 5 只时按实际数量展示，不以弱候选补足。

本设计只调整实时信息页的盘中候选区，不合并或改变独立的“盘末隔夜溢价”模块。

## 方案选择

采用确定性的 100 分统一评分模型。相比按原阶段设置固定优先级，该方案能让板块、量价、MACD、筹码和风险共同决定结果；相比根据历史收益训练动态权重，当前方案不依赖尚未积累完整的候选后验收益数据，结果更稳定且便于解释。

## 候选数据流

1. 沿用现有实时市场、历史日线、板块潜力、60 分钟线、尾盘分钟线和筹码峰数据加载链路。
2. 沿用主板、非 ST、正常交易、基础流动性与底部/热点板块候选预筛，避免对全市场逐只请求分钟线和筹码数据。
3. 将原 observation、trigger、launch 三类结果按 `ts_code` 去重后汇入同一候选池；`resonance_stage` 和 `resonance_type` 继续保留，仅作为底部结构因子和展示说明。
4. 为每只候选计算统一分项得分、风险扣分、总分和建仓等级。
5. 执行保守型硬门槛，剔除不可交易或明显高风险候选。
6. 按建仓等级、总分、板块分、量价分、MACD 分依次排序，最多输出 10 只。

## 统一评分模型

总分计算方式：

`总分 = 板块分 + 量价分 + MACD分 + 筹码分 + 相对强度分 + 底部结构分 - 风险扣分`

总分限制在 0 至 100 分。各正向模块的权重如下。

### 热点板块：30 分

- 板块涨幅和相对大盘强度：8 分。
- 板块上涨家数比例：5 分。
- 板块涨停数量及核心股联动：6 分。
- 板块排名和近期持续性：6 分。
- 板块 MACD 状态：5 分。

热点板块不能仅由单日涨幅判定。板块必须同时参考板块排名、上涨比例、涨停扩散和 MACD 状态，避免一日脉冲被判为持续热点。输出 `sector_hot_status`、`sector_hot_score` 和可解释的 `sector_hot_reason`。

### 量价与主力状态：20 分

- 价格上涨与成交量同步：5 分。
- 量比处于健康区间：4 分。
- 换手率合理：3 分。
- 放量突破或缩量回踩质量：3 分。
- 主力状态：3 分。
- 14:30 后量价承接：2 分。

健康放量优先于极端放量。高位巨量、放量滞涨、异常换手和尾盘跳水不能因成交活跃获得高分，而应进入风险扣分。

### 日线与 60 分钟 MACD：20 分

- 日线 MACD 趋势：10 分。
- 60 分钟 MACD 趋势：10 分。

使用全局 MACD 参数设置，当前为 5/34/5。水上金叉、零轴上方多头延续和柱体增强获得正向分；水下死叉、柱体持续走弱或日线与 60 分钟同时空头不获得正向分，并可能触发硬门槛。

### 筹码峰结构：15 分

- 筹码集中度：4 分。
- 主峰所处历史位置：4 分。
- 当前价与主峰距离：3 分。
- 获利比例：2 分。
- 是否形成可建仓筹码结构：2 分。

筹码数据缺失时该模块记 0 分并输出数据警告。缺失筹码数据的股票不能标记为“立即建仓”，但其他信号足够强时可进入“等待确认”或“观察建仓”。明显上方套牢峰或筹码松散进入风险扣分。

### 市场相对强度与尾盘承接：10 分

- 相对大盘和同行业的强弱：6 分。
- 14:30 后价格承接和收盘位置：4 分。

14:30 前尾盘数据尚不可用时，不将缺失视作零分惩罚；该部分只按已产生的数据计分，并限制最高建仓等级为“等待确认”。

### 底部结构阶段：5 分

- 缩量企稳、涨停回落筑底：基础观察分。
- 底部首阳触发：确认加分。
- 底部放量启动：在量价健康的前提下获得最高分。

阶段只影响 5 分，不再决定独立榜单或绝对排序。

## 风险扣分与硬门槛

风险扣分最多 30 分，包含高位巨量阴线、长上影、放量滞涨、换手过热、短期涨幅过热、筹码峰高位或上方套牢明显、MACD 转弱、尾盘跳水、弱板块孤立上涨等。

所有展示候选必须满足：

- 沪深主板、非 ST/退市、正常成交。
- 最新价格有效，未涨停封板或跌停，具备实际可交易性。
- 无被定义为“一票否决”的高风险项。
- 总分至少 50 分。

“立即建仓”还必须同时满足：

- 总分至少 80 分。
- 热点板块分至少 22/30，且板块 MACD 不是明确空头。
- 量价与主力分至少 14/20。
- 日线和 60 分钟 MACD 不得同时走弱。
- 筹码数据完整、筹码分至少 8/15，且不存在明显上方套牢峰。
- 14:30 后如已有数据，不存在明显抛压或跳水。
- 风险等级为低，且没有高风险项。

## 建仓等级与排序

- 80 至 100 分且满足全部保守硬门槛：`立即建仓`。
- 65 至 79 分，或总分达到 80 但缺少一项即时确认：`等待确认后建仓`。
- 50 至 64 分：`观察建仓`。
- 低于 50 分：不展示。

排序优先级为建仓等级、总分、板块分、量价分、MACD 分、相对强度分，最后用股票代码稳定排序。最多展示 10 只；满足条件不足 5 只时允许显示 0 至 4 只。

## API 与字段

实时信息 `intraday` 区增加：

- `position_candidates`：统一排序后的 0 至 10 只候选。
- `position_candidate_count`：实际候选数量。
- `position_score_version`：评分规则版本和 MACD 参数键。
- `position_filter_debug`：各阶段数量和淘汰原因。

每只候选增加：

- `position_score`、`position_level`、`position_level_reason`。
- `sector_hot_score`、`price_volume_score`、`macd_score`。
- `chip_peak_score`、`relative_tail_score`、`bottom_structure_score`。
- `position_risk_penalty`、`position_risk_items`。
- `position_positive_reasons`、`position_missing_confirmations`。

`intraday.stocks` 与 `position_candidates` 在新版本中返回相同统一列表，方便现有消费者平滑迁移。原 `observation_stocks`、`trigger_stocks`、`launch_stocks` 暂时继续返回兼容数据，但页面不再使用；待确认无外部消费者后再单独移除。

## 页面设计

三张阶段表替换为一张“近期观察与建仓”表，顶部显示候选数量、更新时间和评分版本。默认显示以下列：

- 股票与板块。
- 建仓等级和综合分。
- 板块热点状态及板块分。
- 当前价与涨跌幅。
- 量价/主力分。
- 日线与 60 分钟 MACD。
- 筹码峰及筹码分。
- 相对强度与尾盘承接。
- 风险和主要入选原因。

保留“查看详情”或可展开区域显示全部分项、缺失确认项和风险项，避免主表横向宽度继续膨胀。

## 数据异常与降级

- 分钟数据缺失：保留日线候选但限制最高等级，明确显示“分钟确认缺失”。
- 筹码数据缺失：筹码分为 0，禁止“立即建仓”，不中断整批计算。
- 板块数据缺失：板块分为 0；保守模式下不进入“立即建仓”。
- 单只股票计算失败：记录警告并跳过该股票，不影响其他候选。
- 整体实时数据过期：沿用现有缓存状态和时间提示，不把历史快照伪装成当前建仓信号。

## 测试与验收

- 单元测试覆盖每个分项的边界、风险扣分、硬门槛、等级和稳定排序。
- 回归测试证明原三阶段股票能够去重进入统一池，阶段字段仍保留但不再分别限额。
- 测试证明板块分优先级高于量价，量价优先级高于筹码峰。
- 测试证明高总分但非热点、筹码缺失或 MACD 双弱的股票不能标为“立即建仓”。
- 测试证明低于 50 分不展示，最多 10 只，且不会为了达到 5 只而补入弱候选。
- API 测试覆盖新增字段和旧字段兼容。
- 前端测试覆盖仅渲染一张统一表、等级排序、空状态和详情字段。

验收时使用同一交易时点的数据对比旧三表和新统一榜单，逐只核对总分、分项、硬门槛及落选原因，确保结果可解释。
