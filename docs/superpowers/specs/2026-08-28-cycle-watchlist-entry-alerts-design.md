# 周期关注股票入场提醒设计

## 目标

新增一个独立的“周期关注”模块。用户手动输入长期关注股票的六位代码，系统自动补全交易所后缀，并在每个交易日约每小时检查一次适合 2～5 个交易日持有周期的入场机会。提醒只展示在网页端，分为“低吸提示”“确认介入”和“继续观察”，不使用保证收益或绝对买入措辞。

本模块不替换实时共振、隔夜选股或次日早盘跟进，也不改变它们的候选池和排序。

## 范围

第一版支持：

- 手动添加、修改、暂停、恢复和删除关注股票。
- 六位 A 股代码自动补全 `.SH` 或 `.SZ`。
- 所有关注股票使用同一套入场规则。
- 交易时段定时检查和网页手动检查。
- 保存每次检查结果和状态升级提醒。
- 展示当前判断、触发原因、未满足条件、风险项和历史记录。
- 可选备注与计划低吸价格区间。

第一版不支持：

- 微信、短信、邮件或企业微信推送。
- 北京证券交易所股票。
- 每只股票单独配置技术指标阈值。
- 自动下单、仓位管理或收益保证。
- 基于机器学习的个股自适应参数。

## 代码标准化

输入接受六位数字或已经带后缀的代码，去除首尾空格并统一将后缀转为大写。

- `600`、`601`、`603`、`605`、`688`、`689` 开头补 `.SH`。
- `000`、`001`、`002`、`003`、`300`、`301` 开头补 `.SZ`。
- 已带匹配后缀的代码直接标准化，例如 `600000.sh` 变为 `600000.SH`。
- 后缀与数字段市场不匹配、位数错误、包含非法字符或前缀不在支持范围内时拒绝保存并返回明确错误。
- 第一版不推断 `.BJ`。

股票名称在保存时通过现有市场快照或历史行情补全。名称暂时不可用时允许以代码保存，并在后续检查时再次补全。

重复添加相同标准代码时不创建重复记录。已暂停的记录恢复启用；已启用的记录更新用户提供的备注或计划价格区间。

## 数据模型

### `cycle_watchlist`

- `ts_code`：标准化股票代码，主键。
- `name`：股票名称，可空。
- `note`：用户备注，可空。
- `planned_low_price`、`planned_high_price`：可选计划低吸区间。
- `enabled`：是否参与定时检查。
- `created_at`、`updated_at`：创建和更新时间。
- `last_checked_at`：最近成功或失败检查时间。
- `latest_evaluation_id`：最近有效评估记录，可空。

价格区间若同时填写，要求下限大于零且不高于上限。区间只作为展示和评分辅助，不覆盖统一技术规则。

### `cycle_watch_evaluations`

- `id`：自增主键。
- `ts_code`：关注股票代码。
- `trade_date`、`checked_at`、`data_as_of`：交易日、检查时间和行情时间。
- `status`：`watch`、`low_buy`、`confirmed` 或 `data_delayed`。
- `status_label`：继续观察、低吸提示、确认介入或数据延迟。
- `opportunity_score`：0～100 的机会分。
- `current_price`、`pct_chg`、`support_price`：检查时行情摘要。
- `matched_conditions`、`missing_conditions`、`risk_items`：JSON 数组。
- `invalidation_reason`：失效或降级条件说明。
- `factors`：用于复核的完整因子 JSON。
- `is_new_alert`：本次是否构成网页新提醒。

删除关注股票只停止后续检查并删除 `cycle_watchlist` 当前记录；历史评估记录保留。重新添加相同代码后可以继续查询原历史。

同一股票、同一计划检查时点只保存一次结果。手动检查允许产生新的评估记录，但相同状态不会重复计为新提醒。

## 统一入场规则

系统组合日线、60 分钟和实时行情形成 100 分机会分。具体分值作为集中配置常量实现，并随结果保存规则版本，便于后续回测和调整。

### 日线基础条件

日线部分判断是否适合 2～5 个交易日的低吸交易：

- 中期结构未明显破坏，收盘价没有放量有效跌破 MA20。
- 最近 3～8 个交易日较阶段高点回撤约 3%～10%。
- 当前价格接近 MA10、MA20、近期平台低点或用户计划区间，优先偏离不超过约 2%。
- 最近 3 日均量不高于此前 5 日均量的约 80%。
- 最近 2～3 日不再连续创新低。
- 当前处于合理的 20 日价格位置，避免短期高位追涨。

基础条件不作为全部硬门槛；它们形成可解释评分，但数据不足和明确趋势破坏属于硬降级条件。

### 低吸提示

日线基础分达到 65 分，价格接近有效支撑，且不存在高风险降级条件时输出 `low_buy`。60 分钟尚未确认不阻止低吸提示，但结果必须列出尚未满足的确认条件。

### 确认介入

日线基础分合格，并且以下盘中确认至少满足两项时输出 `confirmed`：

- 60 分钟 MACD 柱缩短、金叉或由负转正。
- 60 分钟 KDJ 低位金叉。
- 实时价格重新站上日内均价或日线 MA5。
- 突破前一日高点或最近 3 日最高收盘价。
- 量比达到约 1.0～1.2 且上涨放量。

确认介入按机会分、确认项数量和相对强度排序。

### 继续观察与风险降级

未达到低吸条件时输出 `watch`，并列出距离最近触发条件的差距。出现以下情况时降低评分或强制保持观察：

- 放量有效跌破 MA20 或计划失效价。
- 连续大阴线或仍在加速创新低。
- 近期涨幅过大、处于 20 日高位或接近涨停，存在追高风险。
- 日线或 60 分钟行情不足。

当前数据不可用时输出 `data_delayed`，保留并引用上一条有效判断，不将缺失数据解释为“暂不参与”。

## 新提醒规则

状态优先级为：

`data_delayed < watch < low_buy < confirmed`

只有当前有效状态相对上一条有效状态升级时，`is_new_alert` 才为真。相同状态的分数变化、重复定时检查或页面刷新不重复增加提醒数量。股票从高状态降级后，未来再次升级可以产生新的提醒。

网页顶部显示当日尚未查看的新提醒数量。用户打开周期关注页后可以将当前提醒标记为已读；已读状态不改变评估内容。

## 检查调度

Java 服务使用现有 Spring 调度能力，在 Asia/Shanghai 时区的以下时点调用 Python 批量检查接口：

- 09:35
- 10:35
- 11:25
- 13:30
- 14:30
- 14:55

Python 服务再次校验交易日和交易时段，并以 `trade_date + schedule_slot` 保证幂等。午休和非交易日不检查。

页面加载时，如果启用股票的最近结果已超过当前计划时点，可触发一次带幂等键的补检。用户也可以手动立即检查全部或单只股票；并发检查请求使用服务锁或数据库幂等约束避免重复执行。

## 服务与接口

新增独立 `cycle_watch_service.py`，负责代码标准化、持久化、行情加载、评分、提醒升级判断和结果组装。行情读取复用现有市场快照、近期日线、60 分钟缓存及实时数据加载器，不复制底层数据源实现。

Python API：

- `GET /api/cycle-watchlist`
- `POST /api/cycle-watchlist`
- `PATCH /api/cycle-watchlist/{ts_code}`
- `DELETE /api/cycle-watchlist/{ts_code}`
- `POST /api/cycle-watchlist/check`
- `GET /api/cycle-watchlist/{ts_code}/history`
- `POST /api/cycle-watchlist/alerts/read`

Java 的 `QuantPythonClient` 和 `QuantController` 暴露对应 `/api/quant/cycle-watchlist` 路径。创建和修改请求使用明确 DTO 或受控字段映射，限制备注长度和历史查询条数。

## 网页设计

新增“周期关注”页签。

### 关注管理

输入框只要求股票代码；备注和计划低吸区间为可选项。列表支持暂停、恢复、编辑和删除。删除操作需要用户确认。

### 今日机会

分为三个区域并独立排序：

- 确认介入：机会分、确认数量、相对强度降序。
- 低吸提示：支撑接近度、缩量程度、机会分降序。
- 继续观察：机会分降序，并突出距离触发最近的条件。

每行展示股票、当前价、涨跌幅、机会分、提示、参考支撑、满足条件、未满足条件、风险项、最近检查时间和行情时间。数据延迟使用独立灰色状态。

### 历史记录

展开单只股票查看当天各计划时点及最近历史评估，展示状态变化而非只显示最新结果。

## 错误处理

- 单只股票行情失败不终止其他股票检查。
- 批量结果包含成功数、失败数和每只失败原因。
- 行情源暂时失败时保留上一条有效结果并标记数据延迟。
- 数据库写入与最新评估引用在同一事务中完成。
- Java 调度失败记录日志，下一计划时点或页面补检可以恢复，不进行密集重试。
- API 校验错误返回 4xx；行情或服务错误返回可解释的 5xx/部分成功结构。

## 兼容与部署

数据库初始化沿用项目现有的按需建表模式。部署脚本加入新 Python 文件，并在 Java 服务启用调度。所有新增接口和页面状态独立命名；现有实时信息缓存键、实时共振候选和其他监控服务不变。

上线后先观察提示记录和未来 1、3、5 日表现。第一版只积累统计数据，不自动调整阈值；后续再基于结果决定是否引入个股波动率自适应。
