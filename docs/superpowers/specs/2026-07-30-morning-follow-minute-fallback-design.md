# 次日早盘跟进分钟数据备用源设计

## 背景与根因

2026-07-30 早盘确认窗口内，外层“次日早盘跟进”持续显示“数据未就绪”。
实际查询表明，Tushare `stk_mins` 对确认日 09:30 至当前已完成分钟返回空表，
而东方财富分时接口能返回同一股票、同一交易日的完整分钟数据。

当前实现只调用 `_cached_minute_bars`，没有在当日分钟线延迟时切换备用数据源，
因此 `_morning_confirmation` 收到空表并固定返回“缺少确认日分钟数据”。

## 目标

- 保持 Tushare 为早盘确认的首选分钟数据源。
- 当 Tushare 返回空表或没有确认日有效分钟时，仅为外层“次日早盘跟进”
  切换东方财富分时接口。
- 让 09:35–10:00 的既有确认规则能使用当日分钟数据计算开盘幅度、当前涨幅
  和首5分钟 VWAP。
- 不改变候选池、评分、严格/宽松分层及早盘风控阈值。

## 隔离边界

## 数据加载流程

新增一个外层早盘确认专用加载函数：

1. 按原时间窗调用 `_cached_minute_bars` 获取 Tushare 1分钟线。
2. 使用既有标准化逻辑检查是否存在确认交易日、09:30–10:00范围内的有效行。
3. 若 Tushare 有有效行，直接返回并标记来源为 `tushare`。
4. 若 Tushare 为空或没有当日有效行，请求东方财富 `trends2` 分时接口。
5. 将东方财富字段转换为统一列：
   `ts_code, trade_time, open, close, high, low, vol, amount`。
6. 再次按确认交易日和时间窗过滤；有效时返回并标记来源为 `eastmoney_fallback`。
7. 两个来源都不可用时返回空表，并保留可展示的失败原因。

上交所代码使用东方财富市场标识 `1`，深交所代码使用 `0`。不认识的代码后缀
不发起备用请求，直接返回数据不可用。

## 缓存与超时

- 东方财富备用结果按 `股票代码 + 确认交易日` 缓存。
- 有效结果缓存20秒，与页面30秒刷新节奏配合。
- 空结果或请求失败短暂缓存5秒，避免同一轮刷新连续重试。
- HTTP连接和读取使用有限超时；单只失败不得中断其余候选。

## 状态与展示

成功取得备用分钟线后，继续调用现有 `_morning_confirmation`：

- 严格候选确认通过：`可以跟进`
- 宽松候选确认通过：`谨慎跟进`
- 触发风控：`放弃`
- 尚未完全满足：`等待确认`

返回行增加 `morning_minute_source`，值为 `tushare`、
`eastmoney_fallback` 或 `unavailable`，用于诊断。现有表格无需新增列。

若两个来源均不可用，状态仍为“数据未就绪”，但原因明确说明
“Tushare当日分钟为空，东方财富备用源未返回有效数据”或具体请求异常。

## 错误处理

- 东方财富 HTTP 非成功、JSON结构异常、交易日不匹配或字段无效均视为备用失败。
- 备用失败只影响对应股票，不能导致整个接口返回失败。
- 不用昨日分钟线冒充确认日数据。
- 不接受尚未完成的未来分钟数据。

## 测试

新增测试覆盖：

1. Tushare 有当日有效分钟时不调用备用源。
2. Tushare 空表时使用东方财富备用分钟线。
3. Tushare 返回旧交易日数据时使用备用源。
4. 备用数据被转换并限制在确认日与当前时间之前。
5. 两个来源均空时仍返回“数据未就绪”并给出明确原因。
6. 单只备用请求异常不影响其他候选。
7. 备用数据驱动宽松候选升级为“谨慎跟进”。
8. 原有服务、API、前端及实时信息隔离回归继续通过。

## 验收标准

- 在 Tushare 当日分钟为空、东方财富可用的情况下，截图中的候选不再统一显示
  “数据未就绪”。
- 早盘状态由真实分钟数据按既有规则计算。
- 外层候选数量和筛选参数不变。
- 内部实时信息服务及 HTML 区块的隔离校验值保持不变。
