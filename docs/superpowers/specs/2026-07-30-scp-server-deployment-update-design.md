# SCP 服务器更新部署文档设计

## 目标

更新 `DEPLOY_SERVER.md`，让使用者可以通过 SCP 将当前版本完整、安全地更新到 Linux 服务器，并正确启用 MySQL 实时缓存。

## 发布方式

本地生成发布压缩包，排除 `.env`、Git 元数据、Python 缓存、Java 构建产物和运行时文件。压缩包上传到服务器 `/tmp` 后，服务器先备份 `.env` 和数据库，再将旧程序目录做可回滚备份，最后解压新版本并恢复 `.env`。

该方式避免 `scp -r` 覆盖过程中出现半更新状态，也避免只上传变更文件时遗漏 Python、Spring 或前端资源。

## 文档修改范围

1. 在目录结构和 MySQL 初始化部分补充 `realtime_cache.py` 以及两个实时缓存表。
2. 重写“更新部署”章节，提供本地打包、SCP 上传、服务器备份、解压、依赖安装、缓存表初始化、Spring 打包、服务重启和 Nginx 刷新的完整命令。
3. 增加发布后验证：
   - Python 与 Spring 健康检查；
   - `realtime_minute_cache`、`realtime_result_cache` 表存在；
   - 实时共振、实时信息的快速查看和强制刷新接口可用；
   - 首次强制刷新后数据库产生缓存记录。
4. 增加失败回滚步骤，恢复上一版程序目录和 `.env` 后重启服务。
5. 更新常见问题，说明首次快速查看可能为空、必须先执行一次强制刷新，以及数据库不可用时服务会回退但查询可能变慢。

## 安全边界

- 发布包绝不包含服务器 `.env`。
- 数据库备份文件保留在服务器，不放入 Web 根目录。
- Python 8000 和 Spring 8081 仅监听本机，由 Nginx 对外代理。
- 文档中的服务器地址、SSH 用户、安装目录和数据库密码均使用占位符。

## 成功标准

按照文档从本地执行打包和 SCP，再从服务器执行更新命令后：

- Python、Spring、Nginx 均正常运行；
- 页面加载新前端资源；
- 两个实时接口支持 `force_refresh=true`；
- 强制刷新写入 MySQL，之后快速查看直接命中缓存；
- 若发布失败，可用文档中的回滚步骤恢复上一版本。
