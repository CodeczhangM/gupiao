# 次日早盘跟进板块设计

## 范围

只改导航栏外层的“隔夜溢价”板块，将其改为“次日早盘跟进”。

以下现有链路必须保持不变：

- “实时信息”页面中的“隔夜选股”表；
- `realtime_info_service.py`；
- `build_overnight_monitor`；
- `/overnight-monitor` 接口及其 Java 代理；
- 实时信息已有隔夜字段、标签、排序和页面显示。

新功能使用独立服务、独立接口和独立测试，避免共享模型互相影响。

## 交易目标

候选股票在前一交易日收盘前后形成观察池。下一交易日不在集合竞价直接追入，而是在 9:35–10:00 检查开盘承接后给出“可以跟进”“等待确认”或“放弃”。

“可以跟进”表示策略条件成立，不代表自动下单或收益保证。早盘买入后按普通 A 股 T+1 约束，下一交易日优先退出。

## 架构

新增 `morning_follow_service.py`，提供 `build_morning_follow_monitor(limit, now)`。新增 Python `/api/morning-follow-monitor` 和 Java `/api/quant/morning-follow-monitor` 代理。

外层页面保留现有 `activeTab === "overnight_monitor"` 和页面状态对象，以减少无关改动，但：

- 菜单和标题改为“次日早盘跟进”；
- `loadOvernightMonitor` 改为请求 `/morning-follow-monitor?limit=10`；
- 表格改为显示前日形态和次日早盘确认字段。

现有 `/overnight-monitor` 不改，继续供原有调用方使用。

## 日期和阶段

服务根据交易日和当前时间确定 `candidate_trade_date`：

- 交易日 14:30 后：使用当日数据，构建或生成下一交易日观察池；
- 交易日 14:30 前：使用上一交易日数据，供当日早盘确认或复核；
- 周末和休市日：使用最近交易日数据，生成下一交易日观察池。

阶段分为：

- `观察池构建中`：交易日 14:30–15:00，尾盘数据仍在变化；
- `明日观察池`：15:00 后、周末或休市日；
- `等待9:35确认`：下一交易日开盘至 9:35；
- `早盘确认`：9:35–10:00；
- `确认结束`：10:00–15:00，保留当日确认结果；
- `数据未就绪`：必要的前日快照或分钟数据不可用。

自动刷新只在 9:30–10:00 和 14:30–15:00 开启。

## 第一阶段：前一日观察池

### 数据修正

当 `daily_basic.volume_ratio` 缺失或非正数时，使用：

`当日成交量 / 最近 5 个更早交易日平均成交量`

作为收盘口径的 `estimated_volume_ratio`。已有正数量比保留为 `effective_volume_ratio`，但页面明确显示“量比”而不伪装成实时官方值。

前一日开盘集合竞价不得参与评分，因为它发生在前一日尾盘之前，不能作为下一日早盘确认。

### 硬筛选

所有候选（包括板块龙头）都必须满足：

- 非 ST；
- 收盘价大于 3 元；
- 当日涨幅 `1.5%–6.5%`；
- 换手率 `2%–12%`；
- `effective_volume_ratio` 为 `1.2–3.2`；
- 成交额至少 2 亿元，对应当前 Tushare `amount >= 200000`；
- 14:30 后涨幅 `0.15%–1.20%`；
- 尾盘量能 `1.2–3.0` 倍；
- 尾盘收盘位置 `>= 0.75`；
- 个股 60 分钟 MACD 满足现有多头/近期金叉模型；
- 板块 60 分钟 MACD/KDJ 不得向下。

龙头身份只加分，不再绕过硬筛选。

### 观察评分

`follow_setup_score` 为 0–100：

- 尾盘强度：30 分；
- 个股 60 分钟趋势：20 分；
- 板块 60 分钟趋势：20 分；
- 换手率、有效量比和成交额：20 分；
- 龙头身份：10 分。

仅返回分数 `>= 70` 的候选。排序依次为：

1. `follow_setup_score`；
2. 板块水上走强；
3. 尾盘收盘位置；
4. 成交额。

## 第二阶段：次日 9:35 确认

对观察池候选拉取次日 9:30 至当前时刻的 1 分钟数据，最多计算到 10:00。

派生字段：

- `morning_open_gap`：次日开盘相对前日收盘；
- `morning_return`：当前价相对前日收盘；
- `morning_vwap`：用 1 分钟收盘价和成交量计算；
- `morning_above_open`；
- `morning_above_vwap`；
- `previous_tail_support`：前日 14:30 后最低价。

状态规则：

### 可以跟进

全部满足：

- 当前时间不早于 9:35；
- 开盘幅度 `-0.5%–2.5%`；
- 当前价不低于前日收盘；
- 当前价不低于次日开盘；
- 当前价不低于前 5 分钟 VWAP；
- 当前涨幅不高于 `3.5%`；
- 当前价不低于前日尾盘承接位。

### 放弃

任一满足：

- 开盘幅度低于 `-1%` 或高于 `3%`；
- 当前涨幅高于 `4%`；
- 当前价跌破前日尾盘承接位；
- 9:35 后同时跌破开盘价和 VWAP。

### 等待确认

未达到“可以跟进”，也未触发“放弃”。

9:35 前统一显示“等待9:35确认”。分钟数据缺失显示“数据未就绪”，不能降级成“可以跟进”。

## 计划字段

每行输出：

- `follow_status`；
- `follow_setup_score`；
- `morning_entry_plan`；
- `t1_exit_plan`；
- `follow_reason`；
- 前日筛选与次日确认的全部可解释字段。

买入计划固定表达为“仅在 9:35–10:00 条件全部成立时考虑跟进”。卖出计划固定为“买入后的下一交易日优先退出：高开分批兑现，低开或跌破前一日尾盘承接位优先控制风险”。不使用“当日止损”等不符合 T+1 的文案。

## 外层页面

标题和菜单改为“次日早盘跟进”。表格显示：

- 股票、板块；
- 前日涨幅、换手率、量比；
- 前日尾盘涨幅、尾盘量能、板块 60 分钟状态；
- 观察分；
- 早盘状态；
- 次日开盘幅度、当前涨幅、VWAP 状态；
- 跟进条件、T+1 退出计划和原因。

内部“实时信息”页面不增加这些字段，不改标题，不改数据源。

## 错误处理与性能

- 先做日线硬筛选，再对有限候选拉取分钟数据；
- 默认最多预取 30 只，最终返回 10 只；
- 单只分钟请求失败时保留其他结果，并记录 `warnings`；
- 早盘分钟数据缺失时不得给出买入结论；
- 复用现有分钟缓存和失败节流机制；
- 新服务使用独立结果缓存，避免污染隔夜模型缓存。

## 测试

### Python 服务

- 量比缺失时用近 5 日均量补全；
- 龙头不能绕过硬筛选；
- 前日开盘竞价不参与观察评分；
- 符合所有前日条件时进入观察池；
- 9:35 前为“等待9:35确认”；
- 9:35 后满足条件为“可以跟进”；
- 高开超过 3%、跌破承接位或同时跌破开盘和 VWAP 为“放弃”；
- 分钟数据缺失为“数据未就绪”；
- T+1 计划不包含当日卖出文案。

### 接口和隔离

- Python 和 Java 新接口正确转发 `limit`；
- 外层页面请求新接口；
- `build_realtime_info` 仍只调用 `build_overnight_monitor`；
- `realtime_info_service.py` 无生产代码修改；
- 实时信息页面“隔夜选股”表结构和字段保持不变。

### 回归验证

- 运行新服务、API、原隔夜服务和实时信息测试；
- 使用当前缓存输出前日硬筛选各阶段数量；
- 在 9:35 场景用受控分钟数据验证三种状态；
- 对真实候选只报告筛选数量和状态，不将单日样本视为收益回测。

## 依据与风险

上交所现行规则规定普通证券买入后在交收前不得卖出，因此早盘跟进计划必须按 T+1 风险设计：
<https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml>

关于中国市场开盘竞价的研究显示，竞价分歧对应的隔夜溢价可能在随后日内反转，因此使用 9:35 后价格、开盘价和 VWAP 做二次确认，而不是直接追集合竞价：
<https://www.sciencedirect.com/science/article/pii/S1544612326004563>

参数是首版工程阈值，需要后续用多交易日样本评估命中率、最大不利波动和 T+1 退出结果后再调整，不构成收益承诺。
