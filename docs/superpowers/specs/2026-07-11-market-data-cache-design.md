# 市场数据增量缓存设计

## 背景与目标

当前选股扫描直接从 Tushare 拉取当日行情和最近 100 个交易日的全市场历史行情。远程接口存在返回条数限制和重试等待，历史区间不完整时还会触发逐日补拉，使 `/api/scan/run` 容易超过上游读取超时。

本改造将扫描使用的全部外部市场数据缓存到 MySQL。首次使用时补齐最近 120 个交易日，后续只同步缺失或仍处于盘中的交易日；策略计算统一从数据库读取最近 100 个完整交易日。目标是让日常扫描通常只产生零次或少量远程请求，同时保留数据更新和失败降级能力。

## 范围

缓存以下 Tushare 数据：

- `daily`：个股每日 OHLC、成交量、成交额和涨跌幅。
- `daily_basic`：换手率、量比、市值等每日指标。
- `stock_basic`：股票名称、行业和上市状态等基础信息。
- `moneyflow_ind_dc`：板块每日资金流。

首次补齐范围为最近 120 个交易日，策略最低完整数据要求为 100 个交易日。缓存的历史数据不自动删除。量化报告表 `quant_reports` 保持现有职责，不作为行情缓存。

## 方案选择

采用 MySQL 标准化表和增量同步，不采用按日期保存 JSON，也不引入 Parquet 文件。标准化表能直接支持日期范围、单只股票、回测和技术详情查询，并与项目现有 MySQL 基础设施保持一致。

## 数据模型

### `market_daily`

保存 `daily` 数据。主键为 `(trade_date, ts_code)`，字段至少包含 `open`、`high`、`low`、`close`、`pre_close`、`change`、`pct_chg`、`vol`、`amount` 和 `updated_at`。为 `ts_code, trade_date` 建立反向查询索引。

### `market_daily_basic`

保存 `daily_basic` 数据。主键为 `(trade_date, ts_code)`，字段覆盖当前扫描所需的 `turnover_rate`、`volume_ratio`、`total_mv` 等值，并保留策略当前读取的其他每日指标。为 `ts_code, trade_date` 建立索引。

### `stock_basic_cache`

保存 `stock_basic` 数据。主键为 `ts_code`，包含名称、行业、地区、市场、上市状态、上市日期和更新时间。每次需要同步新交易日时刷新一次；写入使用 upsert。

### `sector_moneyflow_daily`

保存 `moneyflow_ind_dc` 数据。主键为 `(trade_date, ts_code, content_type)`，包含名称、涨跌幅、收盘值、净流入额及各档资金字段。

### `market_cache_sync`

记录同步状态。唯一键为 `(source_name, trade_date)`，字段包含 `status`、`row_count`、`started_at`、`completed_at`、`updated_at` 和 `error_message`。`status` 使用 `running`、`complete`、`failed`。只有源数据完整写入并提交后才标记为 `complete`。

## 组件边界

新增独立的市场缓存模块，职责分为：

- 表结构初始化和 DataFrame 批量 upsert。
- 查询已完整缓存的交易日和各数据源状态。
- 从缓存加载指定交易日市场快照、最近 N 日历史数据及资金流。
- 协调增量同步、盘中刷新、互斥和失败记录。

`data_service.py` 保留 Tushare 适配职责，对外的现有数据获取函数改为先协调缓存，再从数据库返回 DataFrame。策略层不直接依赖数据库，现有 DataFrame 接口保持兼容。

## 同步流程

扫描触发时执行以下流程：

1. 从交易日历获取截至当前时间最近 120 个交易日。
2. 初始化缓存表，并读取各数据源的完整同步状态。
3. 首次使用时补齐 120 日；后续只处理缺失、失败或需要盘中刷新的日期。
4. 对每个交易日分别拉取 `daily` 和 `daily_basic`。数据为空时不标记完成。
5. 拉取成功后，在单个数据库事务内覆盖该数据源该日期的旧行、批量 upsert 新行，并把同步状态标记为完成。
6. 需要同步新日期时刷新 `stock_basic`。基础信息刷新失败不会破坏已有基础信息，但记录同步警告。
7. 同步对应日期的 `moneyflow_ind_dc`。资金流允许上游尚未发布；此时记录失败或空状态，扫描可继续使用最近可用资金流。
8. 从数据库选择最近完整的市场交易日，组装当日 `daily + daily_basic + stock_basic` 快照，并读取截至该日最近 100 个完整交易日的日线。

同步按日期从旧到新执行，使中途失败时数据库仍拥有连续的最大可用历史窗口。

## 当日刷新规则

时间判断统一使用 `Asia/Shanghai`：

- 当前日期不是交易日时，不创建当天同步任务。
- 交易日 15:30 前，每次扫描都重新同步当天数据并覆盖缓存。
- 交易日 15:30 后，当天各必需数据源已有一次完整同步便直接复用。
- 历史日期一旦标记完整，不再自动重复请求；管理接口可通过强制参数重拉。

## 并发与一致性

进程内使用互斥锁，确保同一 Python 进程只有一个缓存同步任务。数据库的同步状态唯一键防止重复状态记录。行情数据按来源和日期在事务内写入，远程拉取在事务外完成，避免长事务占用连接。

覆盖刷新采用“拉取完成后删除该日期旧行并批量写入新行”的同一事务。写入或校验失败则回滚，原有完整缓存继续可用。

本阶段不实现跨多实例分布式锁；当前部署为单个 Uvicorn 服务实例。若未来启用多实例，再扩展 MySQL advisory lock。

## 失败与降级

- 远程同步失败时记录来源、日期和错误，不把该日期标记为完整。
- 若数据库已有至少 100 个共同完整交易日，扫描使用最近完整交易日继续执行，并在报告响应中加入缓存日期与同步警告。
- 若不足 100 个完整交易日，扫描返回明确错误，说明已有天数、所需天数和最后一次同步错误。
- 当日行情尚未发布时回退到最近完整交易日，不用空数据覆盖缓存。
- `stock_basic` 或资金流失败时允许使用最近成功缓存；日线和每日指标是市场快照的必需数据源。

## API

新增 FastAPI 管理接口：

- `POST /api/cache/sync`：执行增量同步。支持 `force_current` 强制刷新当前交易日；默认只同步缺失数据。
- `GET /api/cache/status`：返回各数据源最新完整日期、完整天数、最近同步状态、行数、时间和错误。

Spring 服务增加对应的 `/api/quant/cache/sync` 和 `/api/quant/cache/status` 转发接口，保持前端统一访问路径。现有 `/api/scan/run` 请求结构保持不变。

扫描报告增加可选元数据：

- `data_trade_date`：实际使用的缓存交易日。
- `cache_updated`：本次请求是否执行了远程同步。
- `cache_warnings`：降级或非必需数据源失败信息列表。

## 前端缓存管理页

Vue 看板左侧导航新增“数据缓存”入口，使用现有 `/api/quant` 统一前缀访问 Spring 转发接口，不直接绑定 Python 服务地址。

缓存页顶部展示完整交易日数量、最新缓存交易日、最近同步时间和整体状态。下方按数据源展示 `daily`、`daily_basic`、`stock_basic`、`moneyflow_ind_dc` 的最新日期、状态、记录数及最近错误；接口字段缺失或空数据库时显示 `--`。

页面提供“增量同步”和“强制刷新当天”两个操作。同步期间两个按钮均禁用并显示“同步中”；成功后自动重新读取 `/cache/status`，失败时复用全局错误提示且不清空已有状态。首次进入页面和执行全局刷新时读取缓存状态。

选股报告包含非空 `cache_warnings` 时，在页面全局错误区域下方显示独立的黄色缓存警告，不把缓存降级误报为扫描失败。正常报告不渲染该区域。

前端只增加缓存状态展示和同步操作，不增加自动轮询、同步进度流或缓存数据明细浏览。本期使用现有 Vue CDN 单页结构和 CSS 视觉体系，不引入新的构建依赖。

## 配置

- `MARKET_CACHE_ENABLED=true`
- `MARKET_CACHE_BOOTSTRAP_DAYS=120`
- `MARKET_CACHE_REQUIRED_DAYS=100`

关闭缓存时保留现有直接请求逻辑，作为故障排查开关。配置值进行范围校验，补齐天数不得小于策略所需天数。

## 初始化与运维

应用启动仅创建缓存表，不自动执行 120 日远程同步，避免启动被阻塞。第一次扫描或手动调用同步接口时执行首次补齐，并输出当前数据源、日期、进度、写入行数和耗时。

README 增加首次同步耗时说明、管理接口示例、环境变量和缓存状态排查命令。部署无需额外文件存储，现有 MySQL 备份流程会同时覆盖行情缓存。

## 测试策略

单元测试覆盖：

- 空数据库首次请求最近 120 个交易日。
- 已缓存 119 日时只拉缺失日期。
- 盘中重复请求覆盖当天，收盘后完整数据直接复用。
- 非交易日不请求当天行情。
- 同日期重复 upsert 不产生重复行。
- 事务写入失败时保留旧缓存且状态为失败。
- 远程失败时在拥有 100 日数据的情况下正确降级。
- 少于 100 日时返回清晰错误。
- 资金流和基础信息失败不阻断必需行情读取。
- 并发同步只执行一次远程拉取。
- DataFrame 字段和现有策略输入保持兼容。

API 测试覆盖同步与状态接口、扫描元数据以及 Spring 转发。最后运行完整 Python 与 Maven 测试套件。

## 不在本期范围

- 定时任务或独立数据同步守护进程。
- 跨多实例分布式锁。
- 自动清理历史行情。
- 保存分钟级或实时行情。
- 将量化报告迁移到新的缓存表。
