# 实时查询数据库混合缓存设计

## 目标

为“实时共振”和“实时信息”增加 MySQL 持久化缓存，提供两种明确模式：

- 快速查看：优先读取最近一次成功筛选结果，目标通常在 1 秒内返回。
- 强制刷新：重新拉取缺失或过期的分钟行情并计算，成功后更新数据库。

缓存不得改变现有筛选条件、排序和多数据源回退规则。

## 当前问题

当前日线行情已经写入 MySQL，但分钟行情、实时筛选结果和最近一次成功结果主要保存在 Python 进程内存中。服务重启、切换进程或缓存键失效后，需要重新请求多个外部分钟行情接口，首次查询通常耗时几十秒。

## 数据模型

### `realtime_minute_cache`

保存筛选过程中实际使用的分钟行情：

- `ts_code`
- `trade_time`
- `freq`：`1min` 或 `60min`
- `open`、`high`、`low`、`close`、`vol`、`amount`
- `source_name`
- `cache_trade_date`：本批分钟数据服务的目标交易日
- `fetched_at`

主键为 `(ts_code, trade_time, freq)`；按 `(cache_trade_date, freq)` 建清理索引。60 分钟指标需要多日历史，因此历史 K 线随目标交易日批次保留，不能按 K 线自身日期仅截取 5 天。

### `realtime_result_cache`

保存可直接返回给页面的成功筛选结果：

- `cache_scope`：`intraday_monitor` 或 `realtime_info`
- `cache_key`：包含影响结果的请求参数，例如 `limit`
- `trade_date`
- `data_as_of`
- `data_status`
- `payload_json`
- `created_at`
- `updated_at`

主键为 `(cache_scope, cache_key, trade_date)`，读取时按 `updated_at` 取最新记录。只有包含有效候选结果的成功刷新才能替换同一交易日记录；失败或空的异常刷新不得覆盖最后一次成功结果。

## 查询流程

### 快速查看

1. 查询进程内短缓存。
2. 未命中时读取 `realtime_result_cache`。
3. 命中后立即返回，设置数据库缓存命中标识和缓存生成时间。
4. 数据库也没有结果时，执行一次完整刷新并保存。

### 强制刷新

1. 绕过最终结果缓存。
2. 分钟数据加载器先查询 `realtime_minute_cache`。
3. 已覆盖请求区间且数据仍新鲜时直接复用。
4. 只对缺少或过期的数据调用现有 Tushare、东方财富、新浪回退链。
5. 外部数据成功后使用批量 upsert 写入分钟缓存。
6. 筛选成功后原子更新 `realtime_result_cache`。
7. 刷新失败时返回最后一次成功结果并标注备用缓存，不覆盖数据库。

## 新鲜度规则

- 盘中分钟缓存必须覆盖到当前请求截止时间附近；允许最多 90 秒行情延迟。
- 午间休市期间以 11:30 为有效截止时间。
- 15:00 后，当日分钟数据视为固定数据，不再因时间流逝失效。
- 历史交易日分钟数据视为固定数据。
- 最终结果快速缓存允许返回最近一次成功结果，并必须展示实际 `data_as_of` 和缓存生成时间。

## 保留与清理

- 分钟行情和最终筛选结果保留最近 5 个交易日。
- 每次成功写入缓存后执行一次有界清理。
- 清理按 `cache_trade_date` 删除不属于最近 5 个目标交易日的分钟批次，同时删除不属于这 5 个交易日的结果快照，不依赖自然日推算。
- 清理失败只记录警告，不影响本次成功结果返回。

## 并发

- 保留当前进程内锁，避免同一进程重复构建。
- 数据库写入使用主键 upsert 和事务，保证结果快照原子替换。
- 同一 `cache_scope/cache_key` 正在刷新时，快速查看继续返回旧缓存。
- 强制刷新按钮保持现有同步接口兼容；前端显示“强制刷新中”。后续如需跨进程后台任务，可在现有表结构上扩展刷新任务表，本次不引入任务队列。

## 接口与界面

- `/api/intraday-monitor` 增加 `force_refresh` 参数，默认 `false`。
- `/api/realtime-info` 保留现有 `force_refresh` 参数。
- 返回增加：
  - `cache_source`：`memory`、`database` 或 `fresh`
  - `cache_updated_at`
  - `result_cache_hit`
- 两个模块提供“快速查看”和“强制刷新”按钮。
- 标题继续显示筛选数据时间，并增加缓存来源状态。

## 错误处理

- 数据库不可用时自动退回当前内存缓存和外部数据源流程。
- 缓存 JSON 损坏时忽略该记录并重新构建。
- 外部刷新失败时优先返回数据库最后一次成功结果。
- 不把异常结果、空白占位结果或数据不可用结果持久化为成功快照。

## 测试与验收

- 数据库表初始化、分钟行情 upsert、区间读取和 5 个交易日清理测试。
- 快速查看数据库命中时不得调用外部分钟数据源。
- 强制刷新必须绕过最终结果缓存，但可以复用新鲜分钟数据。
- 过期分钟数据必须触发现有外部数据源回退链。
- 刷新失败不得覆盖成功结果，并能返回备用缓存。
- 两个接口和两个按钮的参数、状态与文案测试。
- 全量 Python、前端和 Java 测试通过。
- 服务重启后的快速查看使用数据库缓存，目标通常在 1 秒内返回。
